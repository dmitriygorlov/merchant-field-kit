# Merchant Field Kit

[English](../README.md) · **Русский** · [Srpski (latinica)](README.sr-Latn.md)

Прикладной анализ данных для интернет-магазинов. **Какую выручку ждать в ближайшие четыре недели?** Прогноз выручки помогает планировать продажи, а прогноз в штуках помогает принимать решения о запасах. XYZ показывает, какие товары продаются стабильно, а какие труднее прогнозировать.

## Запуск на своём компьютере

```sh
docker build -t merchant-field-kit .
docker run --rm -p 127.0.0.1:8501:8501 merchant-field-kit
```

Если удобнее Python 3.12, см. [команды установки и запуска](../README.md#run-locally). Откройте [localhost:8501](http://localhost:8501), начните с учебного магазина и выберите выручку, штуки или оба показателя. Прогноз на 28 дней можно скачать в CSV. Интернет нужен для установки, но не для расчёта. При локальном запуске файл остаётся на вашем компьютере. Данные покупателей не нужны.

## Что можно загрузить

| Режим | Столбцы | Пример |
|---|---|---|
| Дневные итоги | `date`, `revenue` и/или `units_ordered` | [CSV по дням](../examples/sample_shop.csv) |
| Строки заказов | `date`, `sku`, `revenue` и/или `units_ordered`. Если есть штуки, вместо `revenue` можно указать `unit_price`. | [CSV со строками](../examples/sample_orders.csv) |

Используйте CSV в UTF-8 размером до 1 МБ и минимум **112 календарных дней**. В дневных итогах не должно быть пропусков: ставьте ноль только там, где точно не было продаж. В режиме строк заказов дни без строк между началом и концом выгрузки считаются нулевыми, поэтому выгрузка должна быть полной. Не смешивайте валюты, выручку и прибыль или суммы до и после скидок. Обработайте возвраты до импорта. Даты должны соответствовать часовому поясу магазина. Лучше всего ISO; если день и месяц можно перепутать, укажите порядок явно.

## Как читать результат

Prophet сравнивается с повторением последних семи дней и средним за последние 28 дней. Для каждого исторического окна модели видят только то, что было известно до него. Ошибка выражается в деньгах за день или в штуках за день. Выручка не равна прибыли, а прогноз штук не говорит, сколько заказать. Акции, отсутствие товара и изменения ассортимента влияют на оба прогноза.

Для XYZ нужны строки заказов с кодами товаров и количеством штук. Метод сравнивает недельные продажи по SKU на полных неделях с понедельника по воскресенье. X означает более стабильные продажи, Y более переменные, Z самые нестабильные. Это не рейтинг по выручке. При недостатке истории класс не присваивается.

[Проверка на данных реального магазина](benchmark.md) относится только к штукам. Она не подтверждает точность прогноза выручки или рост продаж.
